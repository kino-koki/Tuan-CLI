# 测试驱动与自测闭环

质量不是测出来的，是写的时候就想好怎么验证。

## 先问「怎么算对」
动手前先定义成功标准：输入 A 必须得到 B；边界 C 必须报错；并发 D 不能丢数据。写不出标准 = 没想清需求。

## 三层测试
- 单元：纯函数/独立逻辑， fastest、最多。给边界值和异常用例。
- 集成：模块怎么协作（DB、网络、文件系统）——用假对象/fixture 隔离外部。
- 端到端：只覆盖关键用户路径，贵而少。

## TDD（可选但强）
红→绿→重构：先写会失败的测试，再写最小实现让它过，最后在测试保护下重构。测试即规格。

## 自测闭环
- 改完立刻 run_tests。红了就读失败信息（哪个断言、期望 vs 实际），定位再修，别「再跑一次试试」。
- 修 bug 先补一个能复现它的测试，确保它真的死了且不回潮。
- 覆盖率看「关键路径」而非追求数字。100% 覆盖的废测试等于零覆盖。

## 测试即文档
好测试名字就是用例：「test_空购物车结算返回零元」。新人读测试比读文档学得快。
