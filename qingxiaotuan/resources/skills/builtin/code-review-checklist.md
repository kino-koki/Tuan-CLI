# 代码审查清单

别逐行读，按风险维度扫。每一条都是「这里最容易出事」。

## 正确性
- 边界：空集合、空字符串、0、负数、None、超大输入。
- 循环/递归会停吗？下标越界吗？off-by-one 检查一遍。
- 并发：共享状态有锁/原子吗？会不会竞态或死锁？
- 错误处理：异常被吞了吗？失败路径有没有清理资源（文件/连接/锁）？

## 安全
- 用户输入是否校验、转义？SQL 用参数化，Shell 用白名单，HTML 防 XSS。
- 不把密钥/令牌写进代码或日志。
- 路径拼接防穿越（../）。

## 接口与契约
- 改了函数签名/返回值/报错类型吗？所有调用方都改了吗？（find_references 查一遍）
- 对外 API 的向后兼容：删字段前先标 deprecated。

## 可维护性
- 命名是否让人一眼懂？函数是否只做一件事、不超过一屏？
- 重复代码抽了吗？魔法数字/字符串有常量吗？
- 注释解释「为什么」了吗？有 AI 腔废话吗？

## 测试
- 改的那条路径有测试覆盖吗？失败用例（异常/边界）有吗？
- 跑了 run_tests 且全绿吗？

## 收尾
- git_status 看一下：有没有误改、遗留调试代码、大文件进仓？
- 自己先 review 一遍再求 review，别把脏活丢给别人。
