# 安全重构法则

重构 = 改结构不改行为。一旦行为变了，那叫改功能，不是重构。

## 前提
- 先有测试这把安全网。没有测试就先补关键路径测试，否则重构是裸奔。
- 小步、高频提交。每步都能独立回退，别攒一大坨再测。

## 步骤
1. 选一个最小目标： rename / 提函数 / 消重复 / 降嵌套，一次一个。
2. 跑测试建基线 → 改 → 再跑测试。红了立刻停，说明行为变了，回退。
3. 用 find_references 确认影响面，改名先全局搜再改，别漏调用方。

## 手法
- 重命名：先 IDE/全局替换，再编译跑测试验证。
- 提取函数：把一段逻辑抽出来，入参出参明确，原处变成一行调用。
- 消除重复：先让两份代码长得一模一样，再抽公共——直接抽「相似」会抽出不稳定的抽象。
- 降嵌套：提前 return（guard clause）干掉深层 if；箭头代码立刻清爽。

## 红线
- 不动公共接口语义（入参含义、返回、异常类型）。要改就先标 deprecated 并通知调用方。
- 重构别顺手「顺带优化逻辑」——把行为和结构混在一起，出事分不清是谁的锅。
- 大文件用 edit_file 精确替换，别整个重写（review 看不出改了啥）。
