# 借鉴开源实现

遇到「这个功能我大概知道要做什么，但拿不准社区里成熟的写法」时，不要凭空硬写，也不要整段照搬。去 GitHub 找相似项目，**借思路、抄结构、不抄代码**。

## 何时用
- 实现某个算法 / 协议 / 解析器 / 交互模式，缺乏现成把握；
- 需要对照成熟项目的边界处理、错误处理、接口设计；
- 想确认「业界一般怎么做」以避免自创反模式。

## 怎么做
1. 用 `qxt gh borrow "<任务或关键词>"` 让青小团自主检索相似开源项目并取回代表性片段（已带仓库 URL + 许可证署名）。
   - 例如：`qxt gh borrow "python sse streaming server"`、`qxt gh borrow "terminal spinner ansi"`。
   - 也可 `qxt gh search repos "<关键词>"` / `qxt gh search code "<关键词>"` 先看有哪些候选。
2. 读回的片段只用于**理解思路与接口形状**，不要逐字复制。
3. 落地时按青小团项目的命名 / 类型 / 错误处理规范**重写**，并在注释或 PR 描述里注明来源仓库与许可证（尊重 MIT/Apache 等条款）。

## 红线
- 绝不整段照搬他人代码；复制粘贴前先想「这算借鉴还是算抄」。
- 拉取的内容只读取、不执行；不要把 GitHub 代码直接 `eval`/`exec` 进运行时。
- 注意许可证：GPL 类传染性协议要谨慎，避免污染本项目（MIT/Apache-2.0 友好）。
- 借鉴原则（引擎会随结果一起返回）：仅参考实现思路 / 接口设计 / 边界处理，引用须保留原作者署名与许可证。
