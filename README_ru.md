# Tuan-CLI

> **«Model + Harness = Agent.»** — разделяем «как думать» и «как выполнить это безопасно», и отдаём вам оба ключа.
> Безопасный по умолчанию, модельно-нейтральный, чисто на Python харнесс ИИ-агента. `v0.3.4` · MIT · Python ≥ 3.10

> ### Позиционирование: агент safety-first — без жертвования разработчиком
>
> **Безопасность — приоритет, а не опция** — и **прерывание — не замена безопасности**.
>
> - **Безопасность в первую очередь**: опасные команды блокируются *до* их выполнения (превью радиуса поражения → жёсткая красная линия → многоуровневое подтверждение). Каждая запись проходит транзакционный журнал для точного `/undo`.
> - **Семантика безопасности**: YOLO/`--yolo` автоматически одобряет действия, которые обычно требуют подтверждения, но **не** обходит жёсткие красные линии. `--isolation` обеспечивает изоляцию на уровне движка/процесса, чтобы уменьшить радиус воздействия и локализовать сбои; это **не** полноценная системная песочница и не замена подтверждению команд.
> - **Опыт разработчика сохраняется**: чтение/запись файлов, рутинные `git`-операции, установка пакетов, прогон тестов и линтеры получают оценку `none` — **ни одного подтверждения, ни одного блокирования** (`safety_engine.is_benign_dev_command`). Только по-настоящему опасные действия эскалируются до совета или блокировки.
> - **Воспроизводимые замеры**: наша цель — «меньше опасных команд проскакивает, меньше безобидных команд дёргает», и любая цифра, которую мы публикуем, **должна быть воспроизводима третьей стороной** — никаких неподтверждённых абсолютных обещаний. Бенчмарки живут в [`bench/`](bench/README.md): 10k противниковых bash/generic-сэмплов + 5k сэмплов PowerShell + 2.497 ручных bypass-пейлоадов (с ассерциями уровня катастрофических последствий). **Одна команда, `tuan safe bench`, воспроизводит всё локально** (без сети, без модели); `tuan safe report` выдает автономный HTML-отчёт о безопасности. Замер по актуальному коду (2026-10): противниковые 10k → блок-реколл 100 % / флаг-реколл 100 % / ложноположительный 0,45 % (5) / bypass 0; PowerShell 5k → точность 100 % / пропуски 0 / ложноположительные 0; матрица bypass 2.497 пейлоад → bypass 0 / ложноположительный 1 / классы катастрофических намерений 100 % заблокировано. Некие сознательно консервативные эскалации fail-closed остаются (напр. `nc`-пробы портов, `tar|ssh`-пейлоады формы эксфильтрации) и объясняют цифры ложноположительных; повторите локально.
> - **Меж-экосистемная совместимость**: мы не перестраиваем экосистемы — **переиспользуем то, что Claude Code / Hermes Agent уже накопили** на этой машине (скиллы, именованные агенты, память, SOUL-персона, MCP-конфиги). `tuan ecosystem` двигает активы в обе стороны одной командой; `tuan ecosystem link` монтирует tuan обратно в них через MCP. Один харнесс, активы трёх экосистем.

## TL;DR

Ядро идеи: **модель думает, харнесс заставляет это мышление безопасно и контролируемо работать.** Tuan-CLI развязывает «модель» от «хоста»: хот-свап между множеством провайдеров, полный офлайн, откат разрушительных ошибок и просмотр радиуса поражения *до* того, как команда выстрелила. Цель — разумно нейтральный, самодержимый терминальный агент-хост — не заточённый обёртка вокруг одного вендора.

**Чем это НЕ является:** не захваченная обёртка вокруг одной модели (хот-свап / self-host / офлайн — как вы хотите); не прислужник IDE (это инструмент терминала, управляемый через ACP из VSCode/Zed/JetBrains); не единственная хрупкая абстракция (plugin-архитектура с контейнером плагинов для строителей, плюс разовый `setup` для остальных).

## Прямые ответы

**В: Это правда «разработано дома»? Сколько собственное?**
Две вещи, разделённые. **Код — написан нами сами**: ядро и подавляющее большинство возможностей (`core/`, `runtime/`, `arch/`, `tools/`, `ports/`…) построены строка за строкой на Python, согласованные с внешними протоколами только ради интероперабельности. **Идеи и дизайн — позаимствованы** — этот проект сознательно синтезирует концепции из известных агентских проектов, и открыто сказать об этом лучше, чем прятать. Единственная часть, где сохранён даже *стиль*, — это оболочка `--tui`, которая сознательно следует фирменному чувству взаимодействия **Kimi Code** (`#4FA8FF` основной, moon-phase спиннер, двухстрочный статус-бар), приписано в [NOTICE](NOTICE). Полный список — в [Вдохновение и атрибуция](#вдохновение-и-атрибуция). **Код — наш; идеи — общие.**

**В: Почему он блокирует меня перед выполнением команды?**
Фича, а не баг. Опасные команды спрашивают первыми; YOLO уважает жёсткие красные линии. Слишком болтлив? `tuan safe allow <cmd>` для whitelist — не отключайте безопасность.

**В: И когда я заблокирован, я застрял?**
Нет. Каждый блок/подтверждение несёт **команд-осознанные безопасные альтернативы** (`tuan safe suggest <cmd>` доступен в любой момент): `git push --force` → `--force-with-lease`, `rm -rf` → рецепт «в корзину/корзину восстановления», `curl | sh` → «сначала скачайте и проверьте». Мы не просто останавливаем вас — мы ведём вас безопасным путём к цели.

**В: Что на самом деле способен откатить `/undo`?**
Каждую **запись**, прошедшую через журнал: один файл, один шаг, целый раунд. Под капотом — транзакционный журнал + `reverse_transform` из diff + снапшоты контрольных точек. Не панацея, но превращает «ошибся = всё пропало» в «скорее всего вытаскиваем».

**В: Он прочтёт мои личные файлы?**
Область инструментов ограничена domain allow-list, исходящий трафик зажат против эксфильтрации, секреты маскируются в выводе. Значения по умолчанию и что можно настраивать — в [SECURITY.md](SECURITY.md).

**В: Полностью офлайн?**
`tuan models local` для зондирования, `/offline` для управления Ollama. Без сети — без проблем.

**В: Могу ли я написать свои инструменты/plugins?**
Да — метаданные через `@plugin`, `activate(kernel)` + `kernel.provide(...)` / `kernel.require(...)`. Три шага:

```python
from ..core.kernel import Kernel, Plugin

@plugin("my.tool", provides=["loop_registry"])
class MyTool(Plugin):
    def activate(self, kernel):
        def _handler(ctx, query: str) -> str:
            return f"echo: {query}"
        kernel.provide("tools.my", _handler)
```

## Номер версии

**Почему `0.3.4`, а не `1.0`?** Честная семантика [SemVer](https://semver.org/): **версия `0.x` означает, что публичный API (интерфейс CLI, схема конфигурации, протокол инструментов, контракт плагинов) ещё не заморожен** и может меняться между релизами. Tuan-CLI уже предоставляет широкий набор возможностей — защитные шлюзы / транзакционный откат, модельно-независимый хот-свап (58 провайдеров + локальный Ollama), три главных цикла, архитектура плагинов с контейнером плагинов, трёхуровневая память, меж-экосистемная совместимость (MCP / ACP / мост Claude Code / Hermes), субагенты и Swarm, cron и фоновые задачи, режим Goal и точные разрешения — всё покрыто тестами. Но **номер версии отражает стабильность интерфейса, а не полноту функций**: полный набор функций не означает, что API следует замораживать. `1.0` зарезервирован на момент, когда публичный API действительно стабилен и мы сможем пообещать обратную совместимость. До тех пор: ломающие изменения поднимают MINOR внутри `0.x` (с подсказками по миграции), совместимые функции поднимают MINOR, исправления поднимают PATCH (см. [VERSION_POLICY.md](VERSION_POLICY.md)).

| Семантика версии | Значение |
|---|---|
| `0.3.4` (сейчас) | **API ещё не заморожен**: `0.x` допускает ломающие изменения, объявляемые с подсказками по миграции; обратная совместимость не обещана |
| `1.0` (зарезервировано) | Включается, когда публичный API заморожен и обещана обратная совместимость; только тогда ломающие изменения поднимают MAJOR (`2.0`) |

## Вдохновение и атрибуция

Tuan-CLI не свалился с Луны: в дизайне мы сознательно опираемся на следующие известные агентские проекты и протоколы. Перечисляем честно, без утайки (и где возможно отмечаем первоисточник в комментариях кода):

| Источник | Что позаимствовали |
|---|---|
| **DeepSeek Harness / Cordis** | Архитектура «контейнер плагинов + реестр сервисов + append-only шина событий» (помечено в `core/kernel.py`) |
| **Kimi Code** | Ощущение и палитра терминального TUI (см. [NOTICE](NOTICE)) |
| **Claude Code** | Система слэш-команд `/`, именованные агенты (совместимость с `.claude/agents`), режим Goal, DevLoop — выравнивание интерфейсов |
| **Hermes Agent** | Трёхуровневая память, цикл самоэволюции скиллов, SOUL-идентичность, саморегистрирующиеся инструменты, cron-семантика — выравнивание; `tuan ecosystem` синхронизирует память/skills/SOUL двусторонне с ним |
| **ACP (Agent Client Protocol)** | Как client/server выравниваем семантику сообщений и рукопожатия, чтобы IDE мог управлять Tuan-CLI |
| **MCP (Model Context Protocol)** | Как client выравниваем протокол, подключая к экосистеме инструментов |
| **API OpenAI / Anthropic / Google и др.** | Адаптеры провайдеров реализованы по официальной REST-семантике — только адаптация протокола, без копирования внутренностей |

> Граница: **код** — собственный; **протоколы/интерфейсы** — выравниваем; **идеи/дизайн** — заимствуем и переплавляем. Где цитируется конкретная деталь реализации, это объявлено в комментариях кода и в [NOTICE](NOTICE).

## Меж-экосистемная совместимость: Claude Code / Hermes Agent из коробки

Помимо «сначала безопасность» и «модельной нейтральности», третья опора — **не перестраивать экосистемы — переиспользовать то, что другие агентские экосистемы уже накопили.** Скиллы (открытый стандарт SKILL.md), именованные агенты (`.claude/agents`), память и персона (Hermes' `MEMORY.md` / `USER.md` / `SOUL.md`), файлы контекста (`AGENTS.md` / `CLAUDE.md`) и конфигурации MCP-серверов структурно почти идентичны у всех трёх — tuan их перекидывает:

```bash
tuan ecosystem scan                        # зондирует Claude Code / Hermes + их активы (только чтение)
tuan ecosystem import all                  # тащит skills/agents/память/SOUL/MCP-конфиги обеих сторон в tuan
tuan ecosystem export skills --to claude   # skills tuan → .claude/skills (для Hermes: --to hermes)
tuan ecosystem link                        # обратное монтирование: Claude Code/Hermes вызывают tuan через MCP
```

- **Автоматически в сессии**: скиллы, уже установленные Claude Code или Hermes, доступны в tuan сразу (`~/.claude/skills`, `~/.hermes/skills` в пути поиска); `tuan ecosystem serve` выставляет tuan как MCP-сервер, чтобы сессии Claude Code / Hermes получили инструменты `tuan_*` (поиск/запись памяти, список/чтение скиллов, headless-доставка задач).
- **Делегируй, не мигрируй**: инструменты `claude_code_run` / `hermes_run` передают задачи в полное нативное окружение другого агента (его собственная конфигурация, память, скиллы, MCP).
- Полный док: [`docs/ecosystem_bridge.md`](docs/ecosystem_bridge.md) (карта форматов / дизайн безопасности / раскладка).

## Три главных цикла, одна уверенная рука

- **ReActLoop** — подумать → сделать → посмотреть, ритм по умолчанию.
- **PlannerExecuteLoop** — сильная модель планирует, дешёвая выполняет (`router.*` поддерживает отделение plan/execute). Экономит tokens.
- **DevLoop** — пишу-верифицирую-чиню: `/verify` автоматически определяет проект (Python/Node/Rust/Go), выводит команды тестов и самоисцеляет до N раундов.

## Модель безопасности: четыре шлюза + undo с журналом

1. **Статический скоринг** — каждая shell-команда оценивается от `none→critical` через фасад `SafetyEngine.score(params)`, с развертыванием косвенных расширений (IFS, `$VAR`, подстановка команд, ANSI-C/восьмеричные/шестнадцатеричные экскейпы, PowerShell Base64, NFKC; ≤32 рекурсии).
2. **Пре-блокирование по радиусу поражения** — вы видите, что он тронет, *до* того, как выстрелит (`--impact`).
3. **Подложка красных линий YOLO** — YOLO убивает пошаговые подтверждения, но **не может** коснуться жёстких красных линий (`rm` рекурсивный, force-push, `chmod -R 000 /`… никогда автовыполнение).
4. **Транзакционный журнал** — у каждой записи есть след аудита; `/undo` восстанавливает через `reverse_transform` из diff + снапшоты.

Правила всегда разрешают `deny > ask > allow`. Whitelist через `tuan safe allow <cmd>`; никогда не отключайте безопасность ради экономии кликов.

## Бенчмарки безопасности: воспроизводимы одной командой

`tuan safe bench` упаковывает три воспроизводимые наборы в одну команду (полностью локально, без модели — любой третий может прогнать их как есть):

- **Корпус противников** `bench/safety_bench_10k.py` — 10.000 bash/generic команд (сид 20260906, воспроизводимо); сообщает блок-реколл / флаг-реколл / долю ложноположительных / bypasses.
- **Корпус PowerShell** `bench/bench_powershell_safety.py` — 5.000 сэмплов (2.300 опасных / 2.700 безобидных); сообщает точность / пропуски / ложноположительные.
- **Матрица bypass** `bench/bypass_matrix.py` — 2.497 ручных противниковых пейлоадов; помимо паттерн-матчинга утверждает **по классу катастрофического последствия**, что каждый класс катастрофического намерения действительно заблокирован.

```bash
tuan safe bench                 # полный прогон (~3 мин)
tuan safe bench --quick         # быстрая самопроверка (~30 c)
tuan safe bench --check         # сравнение с архивом; exit 1 при регрессии (гейт)
tuan safe report                # автономный HTML-отчёт о безопасности (можно делиться)
tuan safe report --release      # RELEASE: цифры + timestamp + git commit связаны (без устаревших цифр)
```

Замер по актуальному коду (2026-10-25, воспроизводимо через `tuan safe bench`):

| Набор | Размер | Ключевой метрик | Bypasses | Ложноположительные |
|---|---|---|---|---|
| Противниковые | 10.000 | блок-реколл 100 % · флаг-реколл 100 % · FP 0,45 % (5) | 0 | — |
| PowerShell | 5.000 | точность 100 % · пропуски 0 | 0 | 0 |
| Матрица bypass | 2.497 | классы катастрофических намерений 100 % заблокированы | 0 | 1 |

Пометка: матрица bypass сознательно fail-closed и держит несколько консервативных эскалаций (`nc` Unicode-вариант-пробы, `tar|ssh` пейлоады формы эксфильтрации), создающие «безобидно-но-помеченные» ложноположительные; те же консервативные причины стоят за 0,45 % (5) FP в противниковом наборе (5 вариантов одного benign-кейса `tar|ssh`, все лишь помечены, ни одна не заблокирована). Цифры авторитетны, как повторены локально через `tuan safe bench`.

**Гейт CI по цифрам**: job `safety-benchmarks` в `.github/workflows/security-ci.yml` прогоняет все три набора при каждом push и сравнивает с закоммиченным архивом — любой регресс (bypasses, класс катастрофических больше не блокируется полностью, явное повышение FP) **валит CI**. Архив `bench/security-bench.json` соответствует таблице README 1:1.

## Нос-к-носу vs Claude Code: одна команда

Помимо само-замеренных наборов безопасности, `bench/vs_claude.py` запускает **один и тот же набор задач на обоих агентах** и рендерит честное сравнение: та же `bench/tasks.yaml`, те же скрипты приёмки, изолированные workspace, `tuan run -p` против `claude -p --output-format json`.

```bash
python bench/vs_claude.py --dry --tuan .venv/Scripts/tuan.exe   # только проверка фреймворка, без вызовов модели
python bench/vs_claude.py --tuan .venv/Scripts/tuan.exe         # настоящий прогон (нужны работающие эндпоинты с обеих сторон)
python bench/vs_claude.py --task fix_bug --model openrouter/deepseek/deepseek-chat
python bench/vs_claude.py --claude "C:\path\claude.cmd" --json
```

Пишет `bench/vs_report.md` / `.json` / `.html` с проходом, wall-time, стоимостью и счётом отказов в разрешениях на задачу.

**Контракт честности**: раннер сначала зондирует, может ли `claude -p` реально завершить один раунд; если зонд падает, колонка Claude помечается **N/A с точной причиной** — никогда не притворяется, что сравнение состоялось. Цифры становятся значимыми только когда оба эндпоинта работают на вашей машине; такова суть воспроизводимого измерения. Примечание Windows: установленный через npm `claude` — это `.ps1`/`.cmd` shim — скрипт автоматически разрешает настоящий исполняемый файл, и старые версии, отвергающие `--no-input`, обрабатываются через редирект stdin.

## Где ваши идеи работают

- **Память** — три уровня (user/project/session) + SQLite FTS5 (trigram), деградирует в plain-text при отсутствии.
- **Субагенты** — типизированная делегация (general-purpose / explore / plan / coder), изолированные субагенты, конкурентные воркеры и Swarm для резки длинных задач.
- **Cron и фон** — `tuan cron start --detach`; headless-автономия.
- **Хуки** — `PreToolUse` может `block` или переписать `args` (`hooks.allow_edit_args`) — большой шов для строителей.
- **Наблюдаемость** — `/stats`·`/audit`·`/impact`·`/bench`·`/cost`; стоимость на столе.
- **crypto** — AES-GCM(AEAD) через `cryptography`, иначе HMAC-SHA256 потоковый шифр как fallback; `open()` с отсутствующей/подделанной MAC всегда fail-closed.

## Полностью локально и офлайн · без входа в аккаунт

Tuan-CLI **не предлагает входа в аккаунт**: нет привязки GitHub / Apple / DeepSeek, нет OAuth-колбэка, нет токенов на диске. Это осознанно — **всё работает локально, кроме API модели, которую вы настроили сами**.

- **Полностью работоспособен без входа**: файловый ввод-вывод, выполнение команд, память, скиллы, субагенты и защитный шлюз — всё локально.
- **Единственное «облако» — ваш API модели**: ключ ваш, отправляется только на этот эндпоинт, без посредников.
- **Нужен полностью офлайн-контур**: установите Ollama или llama.cpp — `tuan models local` для обнаружения, `tuan models set ollama <модель>` для подключения.

### Настройка ключа API модели

```bash
tuan models set deepseek deepseek-chat   # выбрать провайдера и модель
tuan models                              # интерактивная настройка (ключ в ~/.tuan/.env)
```

Ключи хранятся в `~/.tuan/.env` (права 600, не коммитить); работают и переменные окружения (например, `DEEPSEEK_API_KEY`).
