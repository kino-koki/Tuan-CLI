## В двух словах

Большинство агент-CLI рождаются *обвенчанными с одним провайдером*. Tuan-CLI — наоборот: **шасси без прописанного мозга**. Хот-свап между 55 провайдерами, полностью офлайн, откат фатальных косяков и радиус поражения **до** того, как команда выстрелит. **Модель думает — он держит базу.**

**Чем это НЕ является:** не ребёнок какой-то модели (хот-свап, self-host, офлайн — как захочешь); не придаток IDE (стандартный терминальный инструмент, может управляться через ACP/IDE); не матрёшка (микроядро и плагины — для тех, кто любит крутить; одна `setup` — для тех, кто просто хочет работать).

## Быстрые ответы

**В: Это правда «своя разработка»? Только без вранья.**
Две разные вещи, не путаем. **Код — собственный**: ядро и почти все возможности (`core/`, `runtime/`, `arch/`, `tools/`, `ports/`…) написаны на Python от строчки к строчке с нуля, а с внешними **протоколами** интерфейсы лишь сверяются. Но **идеи и дизайн** действительно позаимствованы и переплавлены из известных агентских проектов — это не то, что стоит прятать, это как раз «стоять на плечах гигантов». **Код — наш; идеи — общие.** Единственное место, где сохранился даже *стиль*, — это оболочка TUI `--tui`: она осознанно повторяет фирменный стиль и палитру **Kimi Code** (`#4FA8FF`, крутящийся moon-лоадер, двухстрочный статус-бар), атрибуция в [NOTICE](NOTICE). Полный список — в разделе [Вдохновение и атрибуция](#вдохновение-и-атрибуция).

**В: Почему ты вечно суёшься перед выполнением команды?**
Фича, а не баг. Опасные команды по умолчанию требуют подтверждения; если YOLO попал в жёсткую красную линию — отказ в любом случае. Надоело — `qxt safe allow <cmd>` и не отключай охрану.

**В: Что умеет откатывать `/undo`?**
Все операции записи, что попали в журнал: один файл, один шаг, целый кусок. Под капотом — транзакционный журнал + `reverse_transform` из diff + снапшоты контрольных точек. Не панацея, но «ошибся = слил» превращается в «скорее всего вытащим обратно».

**В: А если он вычитает мои личные файлы?**
Политика разрешений зажимает инструменты в domain allow-list; исходящий сетевой трафик ограничен, чтобы ничего не вытекло; а те выводы, что уходят наружу, маскируют твои секреты. Безопасность для него не лозунг, а ежедневный KPI.

**В: Полный офлайн?**
`qxt models local` для поиска, `/offline` для управления Ollama. Без сети — тоже работает.

**В: Можно написать свои инструменты/плагины?**
Ещё бы. `@plugin` объявляет метаданные, в `activate(kernel)` регистрируешь/достаёшь сервисы через `kernel.provide(...)` / `kernel.require(...)`. Три шага:

```python
from ..core.kernel import Kernel, Plugin

@plugin("my.tool", provides=["loop_registry"])
class MyTool(Plugin):
    def activate(self, kernel):
        def _handler(ctx, query: str) -> str:
            return f"echo: {query}"
        kernel.provide("tools.my", _handler)
```

## Номер версии и история репозитория (прозрачное раскрытие)

**Почему `0.3.0`, а не `1.0`?** Честная семантика [SemVer](https://semver.org/): **версия `0.x` означает, что публичный API (интерфейс CLI, схема конфигурации, протокол инструментов, контракт плагинов) ещё не заморожен** и может меняться между релизами. Tuan-CLI уже предоставляет широкий набор возможностей — защитные шлюзы / транзакционный откат, независимая от модели горячая замена (55 провайдер + локальный Ollama), три главных цикла, микроядерная плагинная архитектура, трёхуровневая память, экосистемная интероперабельность (мост MCP/ACP/Claude Code/Hermes), субагенты и Swarm, cron и фоновые задачи, режим Goal и точные разрешения — всё покрыто тестами. Но **номер версии отражает стабильность интерфейса, а не полноту функций**: полный набор функций не означает, что API следует замораживать. `1.0` зарезервирован для момента, когда публичный API действительно стабилен и мы можем обещать обратную совместимость. До тех пор: ломающие изменения поднимают MINOR внутри `0.x` (с подсказками по миграции), совместимые функции — MINOR, исправления — PATCH (см. [VERSION_POLICY.md](VERSION_POLICY.md)).

| Семантика версии | Значение |
|---|---|
| `0.3.0` (сейчас) | **API ещё не заморожен**: `0.x` допускает ломающие изменения, о которых сообщается с подсказками по миграции; обратная совместимость не обещана |
| `1.0` (зарезервировано) | Включается, когда публичный API заморожен и обещана обратная совместимость; только тогда ломающие изменения поднимают MAJOR (`2.0`) |

**Примечание об истории Git (прозрачность открытого кода):** история коммитов этого репозитория была **намеренно перестроена 2026-09-26 — ранняя история коммитов была осознанно перезаписана автором**; эволюция по коммитам до этой даты больше не восстанавливается (старые объекты `.git` утрачены). Текущий код полностью проверяем — от архитектуры до реализации; для эволюции функций до 2026-09-26 ориентируйтесь на записи версий в [CHANGELOG.md](CHANGELOG.md) (дисциплина версий не затронута). Мы выбираем честно раскрыть этот факт — без приукрашивания и сокрытия.

## Вдохновение и атрибуция

Tuan-CLI не свалился с Луны: в дизайне мы осознанно опираемся на следующие известные агентские проекты и протоколы. Перечисляем честно, без утайки (и где возможно помечаем первоисточник в комментариях кода):

| Источник | Что позаимствовали |
|---|---|
| **DeepSeek Harness / Cordis** | Архитектура «микроядро + реестр сервисов + append-only шина событий» (помечено в `core/kernel.py`) |
| **Kimi Code** | Ощущение и палитра терминального TUI (см. [NOTICE](NOTICE)) |
| **Claude Code** | Система слэш-команд `/`, именованные агенты (совместимость с `.claude/agents`), режим Goal, DevLoop — выравнивание интерфейсов |
| **ACP (Agent Client Protocol)** | Как server/client выравниваем семантику сообщений и рукопожатия, чтобы IDE мог управлять Tuan-CLI |
| **MCP (Model Context Protocol)** | Как client выравниваем протокол, подключаясь к экосистеме инструментов |
| **API OpenAI / Anthropic / Google и др.** | Адаптеры провайдеров реализованы по официальной REST-семантике — только адаптация протокола, без копирования внутренностей |

> Граница: **код** — собственный; **протоколы/интерфейсы** — выравниваем; **идеи/дизайн** — заимствуем и переплавляем. Где цитируется конкретная деталь реализации, это объявлено в комментариях кода и в [NOTICE](NOTICE).

## Старт за пять минут

```bash
# 1) Ставим (комплект [dev] — всё при себе; нужен только API — бери [openai] [mcp])
git clone <этот репозиторий> && cd tuan-cli

qxt

qxt --print run "Привет, представься в одном предложении"
```

## Три главных цикла — одна и та же стабильность

- **ReActLoop**: подумал → сделал → посмотрел. Ритм по умолчанию.
- **PlannerExecuteLoop**: составил план → исполнил по шагам. Для длинных задач, где «одним прыжком» не выйдет.
- **DevLoop**: непрерывный контур разработчика — правит → тестирует → чинит.

Переключается на лету (например, `/mode plan`), не трогая остальное — одинаковый вход, одинаковые инструменты, одинаковый журнал безопасности.

## Устройство (если любишь читать схемы)

```
cli (commands) ──▶ kernel (микроядро + шина событий + contract)
                       ├── kernel/agent    (циклы ReAct/Planner/Dev, маршрутизация, сжатие, хуки)
                       ├── kernel/models   (роутер, каталог провайдеров, адаптеры)
                       ├── kernel/tools    (реестр, разрешения, диспетчеризация, MCP)
                       ├── kernel/mcp / acp (мосты на обе стороны)
                       └── kernel/session  (память / контекст / cron / аудит / skills)
```

Микроядро отдаёт реестр плагинов, контейнер сервисов и шину событий с изоляцией исключений. Движки — изолированные JSONL-подпроцессы, так что сбой одного не роняет главный цикл.

## Полностью локально и офлайн · без входа в аккаунт

Tuan-CLI **не предлагает вход в аккаунт**: нет привязки GitHub / Apple / DeepSeek, нет OAuth-колбэка, нет токенов на диске. Это осознанно — **всё работает локально, кроме API модели, который вы настроили сами**.

- **Полностью работоспособен без входа**: файловый ввод-вывод, выполнение команд, память, скиллы, субагенты и защитный шлюз — всё локально.
- **Единственное «облако» — ваш API модели**: ключ ваш, отправляется только на этот эндпоинт, без посредников.
- **Нужен полностью офлайн-контур**: поставьте Ollama или llama.cpp — `qxt models local` для обнаружения, `qxt models set ollama <модель>` для подключения.

### Настройка ключа API модели

```bash
qxt models set deepseek deepseek-chat   # выбрать провайдера и модель
qxt models                              # интерактивная настройка (ключ в ~/.qingxiaotuan/.env)
```

Ключи хранятся в `~/.qingxiaotuan/.env` (права 600, не коммитить); работают и переменные окружения (например, `DEEPSEEK_API_KEY`).

> **Прозрачность**: в прежних версиях был вход через GitHub / Apple / DeepSeek (включая путь с токеном веб-сессии). Это противоречило позиционированию «полностью локально и офлайн», а веб-эндпоинт был приватным неподдерживаемым интерфейсом, вызывавшим риск-контроль, — возможность **полностью удалена**. Вызовы модели идут через официальные API с вашим ключом.
