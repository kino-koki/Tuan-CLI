> ### 1. 系统层风险
>
> Android 8.0 已无官方安全补丁，且不具备 Scoped Storage 等现代沙箱机制。本软件不对因系统层历史漏洞（含媒体框架类遗留 CVE、WebView 旧版漏洞、本地提权链）造成的任何损失负责。
>
> 具体已知缺口包括但不限于：
>
> - `WebView` 内核锁定在 Chrome 68 系，官方早已停止安全更新，无法通过 OTA 修复后续披露的远程代码执行漏洞；
> - `MediaCodec` / 媒体框架存在多年累积的堆溢出与 use-after-free 家族缺陷，多数已在 Android 9+ 修复，但 8.0 上永久存在；
> - 无 Scoped Storage，应用默认运行在 legacy storage 模式下，进程隔离依赖 SELinux 与 UID 沙箱，弱于现代版本的按目录隔离；
> - 无 App Links 严格校验、无 `packageVisible` 隐式查询限制，跨应用 Intent 暴露面大于 Android 10+。
>
> 您使用本软件即视为已接受上述系统层历史缺陷带来的全部后果，作者不承担任何因系统层漏洞导致的隐私泄露、数据篡改、恶意代码执行等损失。
>

> ### 2. Agent 行为风险（重点）
>
> 本软件通过 `tuan-remote://` 配对协议连接您的桌面端实例。手机端本身**仅具备"发送 prompt"的能力**，所有执行均在桌面端完成，且桌面端已启用 `SecurityGate(remote=True)` 的 **fail-closed 分类**：命中硬红线直接拒绝，任何分类异常一律保守要求确认，不直接放行。
>
> 但请注意：若桌面端同时开启了高权限模式（例如 YOLO、无界模式、协同模式下的高危工具白名单），**手机发出的请求仍可能间接触发文件写入或命令执行**。桌面端的 `SecurityGate` 是分类与确认机制，不是绝对隔离。
>
> 因此：
>
> - **请勿将已配对的手机交由不可信人员操作**——即便配对 token 已作废，只要桌面端会话保持活跃，手机仍可通过 `send_prompt()` 向 Agent 发请求；
> - 手机丢失或被盗时，请立即在桌面端执行 `/remote-control disconnect` 或从 `Tuan-App` 界面点击"断开手机"，作废当前会话；
> - 若您担心旧设备的安全边界，建议在桌面端为手机会话单独创建一个**低权限的 Agent profile**（关闭 YOLO、限制工具白名单、禁用无界模式），而不是复用日常的高权限桌面会话。
>

> ### 3. 数据责任
>
> 配对 token、会话记录、SOUL 人格与声线克隆文件**均存于本机私有目录**（`/data/data/<package>/`），不上传到任何第三方服务器。但请知悉：
>
> - Android 8.0 使用**全盘加密（FDE）**，强度低于现代版本采用的**文件级加密（FBE，AES-256-XTS）**；
> - FDE 依赖内核启动完成才加密整个分区，冷启动到系统就绪的时间窗内数据以明文形式存在磁盘上；
> - FDE 无 Direct Boot 支持，`BOOT_COMPLETED` 之前的进程访问不到加密数据——这既是保护也是限制，某些后台任务可能无法在开机早期运行；
> - 设备丢失或被物理提取（拆机、焊接 NAND 读取）导致的泄露风险**由您自行承担**。
>
> 作者不会向任何第三方上传您的配对 token、聊天记录、SOUL 人格、声线样本或模型权重。若您不同意，请勿安装本软件。
>

> ### 4. 老机预期
>
> 本版本明确面向 **"极客老机复用 / 备用机"** 场景。以下情况属于预期行为，不在维护与追责范围内：
>
> - 设备老化导致的**存储 I/O 退化**（eMMC 掉速、SSD 寿命耗尽）造成的软件崩溃或数据损坏；
> - **电池鼓包**、电池老化导致的强制关机、数据丢失；
> - 老版本 SoC 的**热降频**（骁龙 660/821 等芯片在持续推理时温度升高触发的时钟下调）导致的 TTS 卡顿或首包延迟上升；
> - **内存不足**（<2 GB RAM）导致的 OOM Kill、Agent 响应超时；
> - 硬件不支持 NNAPI 或 GPU delegate 时的自动回落，可能出现 TTS 首包延迟 > 500ms 的降级体验。
>
> 如您的设备不满足"至少 2 GB RAM + 正常工作的存储"这两个最低条件，本软件不做兼容承诺。

> ### 5. 兼容性与降级
>
> Android 8.0 内置 WebView（Chrome 68 系）**不支持**以下较新标准，相关功能将自动降级或失效，均属已知限制，非缺陷：
>
> - `interactive-widget=resizes-content`（软键盘避让）：Android 8.0 WebView 不识别该 viewport 属性，键盘遮挡输入框时，应用会通过 `window.onresize` 高度差探测兜底，偏移量动态喂给 `#inputbar`，但**在横屏或有刘海屏的设备上可能偏移不准**；
> - `visualViewport` API：Chrome 68 未完整实现，横竖屏切换后的可视区域计算可能与预期有偏差；
> - `env(safe-area-inset-*)`：Chrome 68 未支持，刘海屏 / 挖孔屏区域可能被 UI 元素遮挡；
> - `position: sticky` 在部分滚动容器下表现不稳定，列表页可能出现标题栏"卡住"或"跳开"的视觉异常；
> - `@media (orientation: ...)` 在快速横竖屏切换时可能丢失一次触发；
> - ES2020 及部分现代 CSS 特性需经过 Babel 转译，转译后代码路径与桌面端不完全等价，极少数边缘 case 可能出现行为差异。
>
> 上述问题**均通过应用层的检测与兜底处理**，不影响核心功能（配对、发请求、收推送、TTS 播放）的可用性。若您在设备上遇到本文件未列举的兼容性问题，请记录 `adb logcat` 输出并提交 issue，但作者不承诺在 Android 8.0 上修复所有边缘 case。
