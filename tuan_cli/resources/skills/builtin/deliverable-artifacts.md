# 交付物制作与自检

产出型任务（做一个页面、写一份 PPT、出一张海报）与改代码不同：它的失败
往往**编译通过、看起来也像那么回事**，但交付出去会出问题。本技能给三条硬底线
加一张自检清单。

## 一、零 emoji（硬约束，最常被违反）

产物中**禁止任何 emoji 或彩色 pictograph 字符**。这在交付物里是硬缺陷而非
审美偏好：

- **跨平台渲染不一致**：emoji 靠系统字体渲染，缺字体直接变成豆腐方框；
  Windows / macOS / Linux 的字形、基线、彩色与否各不相同。
- **字体回退**：一个 emoji 就会触发 fallback，可能让整行的字重与字号错乱。
- **导出丢失**：转 PDF / PPT 时 emoji 常常丢失、变形或变成方块。
- **无障碍不达标**：emoji 无法参与对比度计算，屏幕阅读器读作"表情符号"。
- **与图标语言冲突**：正式设计系统有统一图标库（如 Lucide），混用 Unicode
  表情会让界面看起来像没做完。

替代做法：

| 想表达 | 不要 | 应该 |
|---|---|---|
| 成功 / 失败 | emoji 打勾打叉 | 图标库图标，或纯文字标签 |
| 警告 | emoji 警告符 | warning 图标配语义色 |
| 方向 / 流程 | emoji 箭头 | `->` 文本箭头；流程用有序列表 |
| 强调 / 热度 | emoji 星标火焰 | 字重、颜色、留白 |
| 分类 | emoji 分类符 | 标签 (tag) 或图标 |

自检命令（交付前必跑，应零命中）：

```bash
grep -nP '[\x{1F300}-\x{1FAFF}\x{2600}-\x{27BF}\x{2B00}-\x{2BFF}]' <产物文件>
```

注意：**代码、命令、日志、路径、正则里的字符按原样保留，不要替换**——
把 `->` 换成箭头、把表情符从字符串里删掉，都会引入真实 bug。

## 二、字体与排版

- **声明字体栈**：HTML 至少写 `font-family` 回退链；依赖 CDN 字体时必须有
  系统字体兜底，否则对方机器上排版全乱。
- **不要只靠系统默认**：不同系统默认字体差异很大；跨端一致时用 web font 并
  配 `font-display: swap`。
- **行宽与行高**：正文行宽 45-80 字符、行高 1.5-1.7，长段落别顶满整行。
- **字号用相对单位**：`rem` / `em` 或 `%`，不要写死 `px`，否则用户改字号设置无效。
- **响应式下限**：在 360px 宽度下不横向滚动、不重叠、不截断。

## 三、导出与离线可用

- 单文件交付优先：CSS / JS 内联或用相对路径，别依赖一长串 CDN 链接。
- 图片用相对路径或内联 base64，并控制体积（首屏图尽量 < 200KB）。
- 若要转 PPT：确认中文字体可用、页面尺寸比例正确（16:9）、每页信息量克制。
- 深浅色：若要跟随系统，用 `prefers-color-scheme`，并手工校验两套配色。

## 四、交付前自检清单

逐条过，任何一条不过就不要交付：

- [ ] 零 emoji：`grep -nP` 零命中
- [ ] 无占位符残留：搜索 `TODO` / `Lorem ipsum` / `xxx` / `待补充`
- [ ] 链接可达：页面内所有 `href` / `src` 指向真实存在的目标
- [ ] 窄屏可用：360px 下无横向滚动
- [ ] 深浅色都读过（或明确只支持一种，并说明）
- [ ] 键盘可用：交互元素可 Tab 到达，焦点可见
- [ ] 无 console 报错：浏览器控制台干净
- [ ] 标题层级正确：只有一个 h1，标题不跳级
- [ ] 文案无占位、无重复的 Lorem

## 五、汇报方式

交付时**说清三件事**：

1. 产物在哪里（绝对路径）。
2. 怎么打开 / 怎么用（一句话即可）。
3. 已知限制（如"仅支持浅色""字体需联网"），不要藏着让用户自己踩。

不要用表情符号做状态标记，用文字："已生成 3 个页面"而不是打一个勾。
