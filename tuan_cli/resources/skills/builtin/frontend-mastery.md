# 前端开发心法

## 心智模型
- 把 UI 当成「状态的纯函数」：UI = f(state)。少写命令式 DOM 操作，多写声明式渲染。
- 数据只有一条可信来源（single source of truth）。派生的东西用 useMemo/computed，不要另存一份会过期的副本。

## 组件设计
- 组件只做一件事，靠 props 通信，靠 children/插槽组合。能函数组件就别用 class。
- 把「会变的状态」和「纯展示」拆开：展示组件不碰副作用，便于测试与复用。
- 列表必须给稳定 key（不要用数组下标），否则重渲染会错乱、输入会串。

## 状态
- 局部状态用 useState/ref；跨组件用 Context 或状态库；服务端数据用缓存（React Query/SWR）而非自己写 loading 布尔值地狱。
- 不要过早上全局 store。80% 的状态是局部的。

## 性能
- 先量再优化。常见的三把刀：避免不必要的重渲染（memo/正确依赖）、虚拟长列表、代码分割（lazy/动态 import）。
- 图片用现代格式 + 懒加载；大计算丢到 Web Worker，别卡主线程。

## 可访问性（a11y）
- 所有交互元素可键盘到达；按钮用 <button> 而非 <div onClick>；表单有 label 与报错关联。
- 颜色对比度达标，别只用颜色传达信息。

## 自测
- 改完在浏览器真跑一遍关键路径；交互逻辑抽成纯函数做单测；视觉改动截图对比。
