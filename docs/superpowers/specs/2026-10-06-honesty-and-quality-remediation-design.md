## 1. 背景与目标

独立评估发现两类问题：

1. **对外表述与仓库事实脱节**：存在不可核实的绝对化断言（"第一且唯一""领先""护城河"）、自评数据被当作客观结论、以及宣称数字与代码不一致（README 称 51 家供应商，`models/provider_catalog.py` 实际 53 个 `ProviderPreset`）。
2. **结构性风险**：核心文件过大、`arch/` 层镜像化、安全引擎单文件 2074 行、沙箱强隔离依赖后端可用性、`tools/shell.py` 存在执行旁路风险。

**目标**：把"对外宣称"与"仓库内可核实的事实"对齐；在不改变功能行为的前提下降低结构性风险。

## 3. B1 诚信/营销修复（先做，低风险）

### 3.1 五条判定原则（可验收标准）

1. **数字可核实** — 每个数量/断言必须能在仓库内复现，或标注来源；无法核实的改为定性表述。
2. **事实与自评分离** — 自评对比报告必须显式声明"自评、非第三方、5 分制相对位置"，并附评分方法。
3. **去最高级** — 移除"第一且唯一 / 领先 / 护城河 / 遥遥领先 / 唯一 / 最强"等最高级营销词，替换为可验证的具体差异描述。
4. **真材实料保留** — 有证据的卖点（安全基准、测试全绿、微内核架构）保留，统一附"自测 / 可复现"口径。
5. **十语言一致** — 以 `README_zh-CN.md` 为权威母本，10 语言 README 同步，数字口径统一。
