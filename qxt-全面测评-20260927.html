架构上读了 core/kernel.py：确实是微内核——内核自己不带 Agent 能力，只做插件注册/激活、服务注册表（插件按服务名互相发现而非直接 import）、append-only 事件总线（带 _MAX_EVENTS=2000 上限防内存膨胀）。注释里明确写了理念源自 DeepSeek Harness/Cordis，这点 README 也没藏。这种分层让 core 占了将近四分之一代码量但职责清晰，不是一锅粥。

依赖健康度不错：核心运行时只硬依赖 pyyaml / rich / prompt_toolkit / httpx，重家伙（openai SDK、cryptography、pydantic、fastapi、opentelemetry）全是 optional extras，且每个都写了"不装时自动回退"的策略（crypto 退到 CTR+HMAC、otel 退到 urllib 直 POST）。这是成熟项目的做法。

10总评

把它当成一个"认真做安全的开源终端 Agent"来看，完成度是够的：微内核架构干净、依赖策略克制、10 分钟的测试套件全绿（3065 条）、安全基准真能一条命令本地复现且数字不注水。v0.2.017 修复轮把第一版测评抓到的高/中危问题全部处理并回归通过，工程可信度明显回升。

v0.2.018 的生态互操作层是当前最硬的差异化：Claude Code / Hermes Agent 的技能、子代理、记忆、SOUL、MCP 配置三方双向复用（qxt ecosystem），在竞品文档里没有对等物，且资产级端到端已在本机真实跑通（导入、导出、反向挂载全链路）。它还不是护城河——SKILL.md 是开放标准，别人也能做桥，且真实 LLM 会话端到端还没跑（缺凭证/网络）；但它已经足够成为选型时一句话讲清的差异点："装一个，三个生态的积累共用"。
